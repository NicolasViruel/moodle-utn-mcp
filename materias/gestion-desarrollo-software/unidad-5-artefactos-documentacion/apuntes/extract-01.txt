3.   Los  4  pilares  de  docs  as-a-code  
Docs  as  a  Code  se  apoya  en  cuatro  componentes  fundamentales  que  trabajan  juntos  para  
mantener
 
la
 
documentación
 
actualizada,
 
colaborativa
 
y
 
automatizada:
 
3.1  Pilar  1  –  Control  de  versiones  con  git  
Git  no  solo  sirve  para  versionar  código;  funciona  igual  de  bien  para  documentos  de  texto.  Al  
guardar
 
la
 
documentación
 
en
 
Git
 
se
 
obtiene:
 
●  Historial  completo:  se  puede  ver  quién  escribió  cada  línea,  cuándo  y  por  qué.  ●  Ramas  (branches):  se  puede  trabajar  en  una  sección  nueva  sin  afectar  la  
documentación
 
vigente.
 ●  Revertir  cambios:  si  se  comete  un  error,  se  vuelve  a  cualquier  versión  anterior  en  
segundos.
 ●  Trazabilidad:  cuando  algo  está  mal  en  la  documentación,  git  blame  muestra  exactamente  
quién
 
lo
 
cambió.
 
3.2  Pilar  2  –  Formato  de  texto  plano  (Markdown)  
Markdown  permite  escribir  documentación  utilizando  caracteres  simples  de  texto  que  luego  se  
transforma
 
automáticamente
 
en
 
contenido
 
formateado,
 
facilitando
 
su
 
mantenimiento
 
y
 
versionado
 
junto
 
al
 
código.
 
Es
 
el
 
formato
 
estándar
 
en
 
Docs
 
as-a-Code
 
porque:
 
●  Es  legible  sin  renderizar:  se  entiende  incluso  leyendo  el  archivo  crudo.  ●  Es  texto  plano:  Git  puede  comparar  diferencias  línea  por  línea,  al  igual  que  el  código.  ●  Es  universal:  GitHub,  GitLab,  Notion,  Obsidian  y  muchas  otras  herramientas  lo  soportan.  ●  Es  fácil  de  aprender:  la  curva  de  aprendizaje  es  mínima.  
3.3  Pilar  3  –   Revisión  colaborativa  (Pull  Requests)  
En  Docs-as-Code,  cualquier  cambio  en  la  documentación  pasa  por  un  pull  request  (también  
llamado
 
merge
 
request
 
en
 
GitLab),
 
igual
 
que
 
el
 
código.
 
Esto
 
significa
 
que:
 
●  Otro  miembro  del  equipo  debe  revisar  y  aprobar  el  cambio  antes  de  que  se  incorpore.  ●  Se  pueden  hacer  comentarios  línea  por  línea  sobre  partes  específicas  del  texto.  ●  Se  controla  que  la  documentación  sea  precisa  y  esté  bien  escrita  antes  de  publicarse.  ●  Se  distribuye  el  conocimiento  sobre  el  proyecto  entre  todos  los  que  revisan.  
3.4  Pilar  4  –  Automatización  CI/CD  
CI/CD  significa  Integración  Continua  y  Despliegue  Continuo.  En  el  contexto  de  Docs  as  Code,  
es
 
el

que
